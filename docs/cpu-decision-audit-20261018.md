# 標準CPUの選択判断と後攻の防御計画（v1.15.525）

先攻・後攻のルールやカード数値を変えず、標準CPUの計画・選択を改善した。コミット・PUSH・本番公開は行っていない。

| 調査対象 | 見つかった判断 | 修正した比較 |
|---|---|---|
| 社の施し | 現在マナ以内しか探索せず、使えば可能な展開を見落とす | 有効な社を予算に含め、使用価値と温存価値を比較。不足分だけ正規の破壊・死亡時処理で支払う |
| 主計画 | 消費マナをほぼ最優先 | 除去・守護・回復・手札補充・味方の損失・支払いを評価。効果解決後に計画し直す |
| 選定 | 条件を満たす先頭の効果 | 合法な候補の利益と損失を比較。相手の致死打点を止める除去とドローを区別 |
| 一般選択 | 最初の有効候補。候補なしでも0 | 効果を比較し、有効候補なしは-1。条件不成立の枝を選ばない |
| 数字宣言（独往） | 常に最初の数字0 | 宣言したコストで失う両陣営の公開レガシーを比較 |
| 誘・種類別サーチ | 最初の該当カード | 使える時期・盤面不足・守護・除去・重複を比較して手札へ加える |
| 霊視 | 常に何も墓地へ送らない | 墓地起動札・低価値の重複・当面不要な札を比較。必要な札は上に残す |
| リロール | 任意確認を一律承諾し、戻す札を十分比較しない | 現在使える有効札を守り、重複・当面使えない札を候補にする。交換しない選択も行う。山札の上は見ない |
| 捨て札・回収 | 最小コスト／単純な盤面数値。本人の視点が不十分 | 使用価値と墓地での活用を評価。相手CPUが捨てる場合はその本人の視点で評価し、終わったら必ず戻す |
| 任意効果 | 文章に自壊・墓地送り等があれば一律見送り | 既知の効果は利益と代償を比較。安い自軍レリックを消費して大きな脅威を倒す取引も候補 |
| 進化元 | 一般的な対象評価では強い札を選びやすい | 小さい土台を優先し、強い主力を不用意に重ねない。メイン計画の進化・昇華探索も維持 |
| 効果再発動先 | 本体の数値が大きい札 | 対象となる契機の効果を比較 |
| 守護 | 神攻を必ず受け、場の並び順で決まる | 失う守護・倒せる相手・守るライフ／レガシー・残りの攻撃を比較。小さい守護で足りるなら主力を温存 |
| 合計戦闘力・同名制約つき対象 | 大物から順に取り、複数枚の良い組み合わせを逃す | 上限内の組み合わせを探索。「まで」は少ない枚数で得をする選択も認める |
| 疲労が近い攻撃 | 次の疲労を十分考慮しない | 先攻が次の開始時に倒れるなら後攻は攻め急がない。自分の次の疲労も評価 |
| オンライン部屋のCPUへの捨て札依頼 | 実在しない相手クライアントの回答を待ちうる | CPU自身がローカルで選ぶ。人間への委譲経路は維持 |

既に状況評価があったカミ別神技・バウンス・多種族の同時配置等は維持した。「全てを対象」「ランダム」等のカードルール、候補が一意に決まる処理、チュートリアルの指定は不具合として置き換えていない。初心者向けの簡単な判断と、人間の選択画面は標準CPUへ置き換えない。

評価は公開盤面・公開手札枚数・自分の手札と既知のカード情報に基づく。相手の非公開手札や山札の中身は、発動者の判断材料にしない。捨てる本人のCPUに判断を委ねる処理では、その本人が知る手札を使用する。

効果評価は完全な未来シミュレーターではなく、数値化できる即時効果・対象・一部の条件を使う近似。未対応の動的依存や複雑な連鎖について、最適な一手を保証するものではない。未知の対象や条件を勝手に合法とみなして加点しない。

回帰テストは `tests/cpu_standard.test.js`、`tests/kami_ai.test.js`。後攻の社による2コスト展開、社の温存、除去と大型展開の比較、巻き込む味方の損失、選定、一般選択、数字宣言、誘、霊視、リロール、任意の交換、守護の温存、進化元、本人視点の捨て札、疲労、非公開情報の参照禁止、制約付き対象選択等を確認する。

対戦の条件・成績・履歴は [検証レポート](cpu-validation-20261019.md) に保存する。ローカル確認先は http://localhost:8765/index.html 。
